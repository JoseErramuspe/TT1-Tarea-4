## Resp Parte 1
La diferencia entre descargar un proyecto como zip y clonarlo con Git es que el zip descarga solo los archivos, y git clone descarga también el historial de versiones y permite sincronizar cambios con Github.

## Resp Parte 2
El archivo README.md sirve para documentar el proyecto, explicar su funcionamiento, y como se usa.

## Resp Parte 3

## Resp Parte 4
Un commit guarda una instantánea de los cambios realizados en el proyecto y te guardar un historial de versiones.
## Resp Parte 5

Es recomendable trabajar en ramas diferentes a la rama principal porque permite desarrollar y probar cambios sin afectar la versión estable del proyecto. Además, facilita el trabajo colaborativo y la revisión de cambios antes de integrarlos al proyecto.

## Resp Parte 6

El archivo hello.sh no aparece en la salida de git status porque está siendo ignorado por una regla definida en el archivo .gitignore. 
La regla `[Hh][Ee][Ll][Ll][Oo].[Ss][Hh]` indica que Git ignore cualquier archivo llamado hello.sh, aunque las letras están en mayúsculas o minúsculas.

El archivo .gitignore sirve para indicar qué archivos o carpetas Git no debe rastrear ni incluir en los commits. Y se pueden ignorar archivos temporales, ejecutables,  scripts que no deben formar parte del repositorio.

## Resp Parte 7

Un Pull request permite pedir cambios realizados en una rama para que sean revisados antes de que vayan a otra rama, mas que nada la principal. Facilita la revisión de código, la discusión de modificaciones y el trabajo para los desarrolladores.
