1)	Al clonar un repositorio se descarga también el historial de commits y se lo puede modificar y enviar a github. Al descargar un zip se descargan solo los archivos en el estado actual del repositorio y no se tiene conexión con github para realizar o ver cambios.
2)	El archivo README sirve como guía y presentación del proyecto, es donde se explica que hace y como usar el repositorio.
3)	La carpeta Estudiantes y sus archivos aparecen como untracked ya que nunca fueron agregados al área de preparacion por git.
4)	Un commit guarda el estado actual del proyecto para el uso actual y para poder revisar en el futuro si el archivo fue modificado y se quiere ver una versión anterior.
5) Es recomendable trabajar en ramas direfentes a la principal ya que, generalmente, se usa la rama principal para la version estable del proyecto que se muestra el publico mientras que en ramas secundarias se trabaja en mejorar el codigo o agregar funcionalidades sin correr el riesgo de "romper" un programa funcional.
6) El archivo hello.sh no se agrega al area de preparacion ya que el nombre del archivo se encuentra en el gitignore.
7) El archivo gitignore sirve para que git no tenga el cuenta x archivo, sirve para no publicar un archivo con claves u otra informacion sensible o cualquier archivo que no se quiera hacer publico.
8) un pull request sirve para hacer un merge entre una rama secundaria y la principal, en el flujo colaborativo es la etapa final del trabajo separado de una rama secundaria. si se trata de un proyecto open source el pull request sirve para que los cambios hechos para un tercero sean presentados al propietario del proyecto y tal vez posteriormente agregados al proyecto. <br>
<h2>Reflexion final: </h2>
1) lo mas sencillo de la tarea fue la creacion de archivos y carpetas en el repositorio local. <br>
2) lo mas dificil de la tarea fue el push de la rama a github, ya que desconocia el comando necesario. <br>
3) estas herramientas permiten agilizar el trabajo colaborativo al permitir acceder a los cambios realizados por otra persona de forma facil. tambien es util para el trabajo personal ya que permite tener un registro de versiones. <br>
4) considero util el uso de ramas ya que ayudan a preservar la estabilidad del programa mientras permiten la colaboracion y trabajo paralelo.
